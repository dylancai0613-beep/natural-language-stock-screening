# 自然语言智能选股与策略解释器

这是一个用聊天完成选股的演示产品。用户说自己的想法，AI 帮忙把想法整理成具体条件，问清楚含糊的地方；用户确认后，后台用真实数据筛选，再说明每只股票为什么入选、为什么没入选、哪些地方还不能判断。

本项目对这道题的解法是：**先准备一张放在后台的“选股填空试卷”，让客户通过聊天回答，AI 负责代填；填好并确认后，再把答案交给固定的筛选提示词，调用数据和计算工具。**

客户看到的始终是“对话窗口 + 筛选结果”，不需要面对一张技术表格。这里把后台结构叫作“试卷”，只是为了说明我们的设计。

当前本机演示地址：[http://127.0.0.1:4173/](http://127.0.0.1:4173/)。启动方法见第 7 节。**提交用的外部演示网址和源码仓库地址仍待补充**，完成情况见第 14 节。

## 1. 这道题要解决什么问题

题目中的典型需求是：“请查找经营改善、估值合理、走势相对稳定的股票。”

这句话能表达方向，却还不能直接拿来算。比如，“经营改善”看收入还是利润？“估值合理”用市盈率还是其他指标？“稳定”看多长时间、波动多大才算稳定？用户改了某个条件，原来的其他要求是否还保留？

我们把问题分成三件事：

1. **把意思问清楚。** AI 理解用户的话，解释采用的默认理解，并询问是否需要调整。
2. **把条件算准确。** 后台检查条件，再用已经核对过的数据计算，不让 AI 凭印象挑股票。
3. **把结果说清楚。** 展示每项条件的数据、日期和来源，AI 再据此说明结果。

24 小时内，我们优先做完整的这条主线。当前不做交易、回测平台，也没有接通整个 A 股市场的数据。

## 2. 我们的方案：“后台试卷 + 两段提示词 + 数据工具”

### 2.1 为什么先准备试卷

如果每次都让 AI 临时决定需要哪些字段、指标怎么算、缺什么信息，前后两轮就容易使用不同标准，后台也很难执行。

所以，我们先把支持的题目写好。例如市盈率这道题：

| 要填的内容 | 含义 | 当前约定 |
|---|---|---|
| 是否使用 | 用户是否关心这项条件 | 只启用用户涉及的题目 |
| 计算口径 | 用哪一种市盈率 | 默认使用 TTM，即最近十二个月口径 |
| 比较方式 | 低于、不低于、介于某个范围等 | “估值合理”采用产品默认：低于 |
| 数值 | 具体多少倍 | “估值合理”采用产品默认：20 倍 |
| 数据日期 | 用哪一天的数据 | 用户没指定时，使用现有缓存的日期，并说明 |
| 答案来源 | 是用户说的，还是产品默认 | 后台分开记录 |
| 是否确认 | 用户是否同意这样理解 | 必须由用户明确确认 |

**预写的是题目和允许填写的内容，不是客户的答案。** 用户不关心的题目无需填写；支持范围以外的需求，AI 要说明并继续询问，不能临时编一个指标出来。

### 2.2 客户怎么“填写”这张试卷

客户通过自然语言和聊天选项回答，AI 把答案记到后台。客户不需要说“我要填市盈率的比较符和阈值”。

| 客户的说法 | 后台先怎么记录 | 接下来怎么问 |
|---|---|---|
| 估值合理 | 市盈率 TTM 低于 20 倍，标为产品默认 | 这样理解是否合适，要不要改指标或倍数？ |
| 经营改善 | 先采用产品默认：单季度营收同比增速比上一季度提高 | 更关注收入还是利润？采用哪个报告期？ |
| 走势相对稳定 | 先采用产品默认：60 日年化波动率低于 30% | 要调整稳定的衡量方式或数值吗？ |
| 市值比较高 | 记录用户关注总市值，数值暂时空着 | 希望总市值至少多少亿元？ |
| 经营更关注利润，不是收入 | 替换原来的营收条件，其他条件保留 | 是关注扭亏，还是利润增长加快？ |

这些默认值是为了让对话能继续的**产品约定**，不是公认的投资标准。用户可以通过聊天修改。没有预写默认的内容，例如具体财务报告期，不能让模型随意猜。

“利润增长加快”和“扭亏”是两道不同的题：“增长加快”看增速是否比上一季提高；“扭亏”看是否从亏损变为盈利。不能拿“利润同比为正”冒充“增速加快”。

“行业景气”也不能直接当成“单家公司营收改善”。当前没有行业景气指标时，AI 应先说明这一点，再问用户是否愿意采用公司层面的替代指标。

### 2.3 整个流程

~~~text
用户说选股想法，或点击聊天里的选项
                  ↓
第一段提示词：请 AI 理解本轮意思，填写已有试卷
                  ↓
后台检查：题目是否受支持？数值、单位、日期是否合适？
                  ↓
不清楚的地方，由 AI 继续追问；已明确的其他条件保留
                  ↓
AI 用普通话复述当前条件，用户决定是否修改
                  ↓
用户明确确认，后台锁定这份答案
                  ↓
第二段提示词 + 已确认答案 + 两个只读工具
                  ↓
AI 请求读取数据，再请求运行筛选
                  ↓
程序逐项比较真实数据，得到满足 / 不满足 / 待核验
                  ↓
结果区显示股票和证据；AI 根据同一份结果解释原因
                  ↓
用户继续修改 → 重新确认 → 同一份数据上比较结果变化
~~~

第一段和第二段提示词是事先写好的工作要求，**真实问答由每轮 DeepSeek API 调用生成**。聊天选项也是模型根据当前对话生成的，不是一套写死的场景按钮。确认按钮、加载状态和错误提示由页面及后台处理。

## 3. 一轮完整对话中，后台究竟做了什么

下面是一条说明流程的例子。实际措辞和追问顺序由模型生成，不要求每次和这里逐字相同。

1. 用户说：“经营改善、估值合理、走势相对稳定。”
2. AI 读取后台题目，先记录营收增速改善、市盈率低于 20 倍、60 日年化波动率低于 30% 这三项默认理解，并说明哪些数据暂时没有。
3. AI 询问用户是否调整这些理解，补充必要的报告期。用户仍然只是在聊天。
4. 用户说：“经营改善更关注利润，不是收入。”AI 追问是扭亏还是利润增速加快，不把原来的估值和走势条件丢掉。
5. 用户说：“利润增长加快，用 2026-Q3，PE 放宽到 30 倍，走势不变。”AI 更新利润题、报告期和市盈率数值，保留走势条件。
6. 后台检查是否还有缺项或不支持的要求。如果有，继续通过模型追问；如果没有，给用户明确确认的入口。
7. 用户确认后，这份答案才交给筛选阶段。模型不能自己把“已确认”写成真。
8. 筛选阶段请求读取缓存、运行计算。三只股票的市盈率都低于 30 倍，但利润增速和波动率没有真实数据，因此整体是三只待核验，不能说三只全部入选。

这里最重要的是区分两件事：

- **用户还没说清楚。** 例如“市值比较高”没有给金额，需要继续问。
- **用户已经说清楚，但我们缺数据。** 例如利润指标和报告期都明确了，当前却没有对应财报数据。这时不应该让用户反复回答同一个问题，而应保留条件并显示待核验。

## 4. 试卷填好以后，怎样交给提示词

不是把一句聊天摘要直接交给模型，让它自由推荐股票。实际交给筛选阶段的是**后台保存并经过用户确认的具体答案**。

例如，用户最终确认的答案可以用下面的大白话表示：

| 项目 | 已确认答案 |
|---|---|
| 股票范围 | 贵州茅台、平安银行、招商银行这三只本地样本 |
| 数据日期 | 2026-11-09 |
| 市盈率 | TTM 低于 20 倍 |
| 总市值 | 不低于 500 亿元，后台统一存成 50000000000 元 |
| 经营改善 | 2025-Q4 单季度营收同比增速比上一季度提高 |
| 条件之间的关系 | 必须全部满足 |

后台会把这份答案复制并锁定，再与筛选提示词一起发送给 DeepSeek。模型会同时看到两个可用工具，像两个受限制的操作按钮：

| 工具名称 | 大白话解释 | 能不能改条件 |
|---|---|---|
| get_snapshot | 看当前已经准备好的真实数据，以及日期和覆盖范围 | 不能 |
| run_screen | 按锁定的答案，请程序逐项比较数据 | 不能 |

两个工具都不接受模型传来的新股票池、新数值、代码或查询语句。它们使用后台已经确认的答案。模型不能自己写一份“入选股票名单”来代替程序结果。

算完后，工具把每只股票的结果和依据返回给模型。模型再用普通话解释，页面则显示程序实际算出的结果。

**“条件写完整”“数据够用”“解释写成功”是三回事：**

- 条件没完整，先补充和确认。
- 条件完整但缺数据，结果中显示待核验。
- 结果已经算好，但模型解释超时或没有通过数值、引用检查，仍保留真实结果和证据；用户可以单独点击“重新生成解释”，无需重新筛选。

解释校验会检查格式、数字是否有依据、引用是否存在。这些检查能拦住一部分错误，不等于已经证明模型每一句自然语言都绝对正确。结果表和原始数据证据是复核依据。

## 5. AI、后台程序和金融数据各负责什么

| 角色 | 负责的事 | 具体例子 |
|---|---|---|
| DeepSeek | 理解语言、选择已有题目、填写答案、提出追问、生成聊天选项、请求工具、解释结果 | 理解“更关注利润”并追问具体含义 |
| 后台程序 | 管顺序、检查允许填写的字段、处理单位、保留其他条件、管理确认状态、执行比较 | 把 500 亿元换成元，按数值比较，不让模型代替用户确认 |
| 金融数据工具及本地缓存 | 提供有来源的实际数值、日期、单位和原始字段 | iFinD 返回的 PE TTM 和总市值 |
| 用户 | 决定如何理解自己的需求，并确认最终条件 | 采用默认值，或把 PE 改成低于 30 倍 |

这几个常见英文名字在项目里的意思是：

| 名字 | 可以怎么理解 | 放在哪里 |
|---|---|---|
| contracts | 题目和填空规则：问什么、哪些空必填、允许什么答案、默认是什么 | contracts/，按指标中文名分文件 |
| metrics | 指标说明书：这个指标代表什么、怎么算、单位是什么、需要什么数据 | config/metrics/，与题目使用同名文件 |
| prompt | 写给模型的工作要求：这一步要做什么、能做什么、不能做什么 | config/prompts/ |
| runtime | 后台把消息、试卷、模型和工具接起来的运行过程 | 主要由 http-server.cjs 调度 |
| validation | 后台检查“这份答案是否填完整、合法且已确认”的结果 | 由程序计算，不信任模型自报 |

例如，contracts/市盈率.json 规定“市盈率这道题怎么填”；config/metrics/市盈率.json 说明“市盈率是什么、默认解释是什么、从哪个数据字段取值”。真正拿数值比较的代码在 evaluator.cjs。

**指标说明书里写了公式，不代表数据已经接通，也不代表程序会自动执行这条公式。** 当前实际比较器只接通了本地样本的 PE 和总市值；其他题目仍可用于澄清和记录需求，结果必须如实标为待核验。

默认值优先级是：用户本轮明确给出的值优先；用户没改的内容沿用上一轮；新启用的题目可以采用预写默认。默认值要标明来源，不冒充用户原话。

## 6. 怎么演示这个产品

### 6.1 最短路径：先看到真实筛选结果

在页面输入：

> 找市盈率 TTM 低于 20 倍的股票，使用当前三只样本和缓存日期。

看完模型解释后，点击“确认条件”，再点击“执行筛选”。在当前这份缓存中，应该看到两只入选、一只未入选。展开证据，可以看到各自的实际市盈率。

继续输入：

> 市盈率改成低于 30 倍，其他条件不变。

页面会提示旧结果属于上一轮条件。重新确认并执行后，三只都满足；在同一份数据上，有一只股票的整体状态发生变化。这样可以展示题目要求的“条件变化会带来什么影响”。

这个比较只比较同一份缓存上的筛选状态，不是历史回测，也不是收益变化。

### 6.2 完整路径：保留缺数据的条件

另开一个新对话，输入：

> 在当前三只样本中查找市盈率 TTM 低于 20 倍、总市值不低于 500 亿元，并且 2025-Q4 单季度营收同比增速较上季提高的股票，使用缓存日期。

确认后执行。当前已验证的结果是：

| 股票 | 整体结果 | 原因 |
|---|---|---|
| 贵州茅台 | 未入选 | 市盈率 21.9856 倍，不满足低于 20 倍；市值条件满足，营收改善仍缺数据 |
| 平安银行 | 待核验 | 市盈率和市值满足，但营收改善缺数据 |
| 招商银行 | 待核验 | 市盈率和市值满足，但营收改善缺数据 |

因此总计是 **0 只入选、1 只未入选、2 只待核验**。缺数据不等于没通过，也不能当成已经通过。

### 6.3 体验自然澄清

输入题目原句：

> 请查找经营改善、估值合理、走势相对稳定的股票。

再根据模型追问回复“经营更关注利润，不是收入”，或者修改估值、走势的理解。这个例子主要展示后台试卷如何逐步填好；经营和走势指标目前没有真实数据，不能用它宣称已经完成全市场三维筛选。

以上演示会调用真实模型。每次点击模型生成的聊天选项，也相当于发送一条回复，会消耗一次或多次模型请求；不要把反复演示当成免费本地测试。

## 7. 怎么在本机运行

### 7.1 准备环境

当前实现使用 Node.js 24，自带的网页和后台服务共用一个进程，没有第三方依赖需要安装，也不需要 Python 环境或数据库。

源码在本机的位置是 D:\project\同花顺笔试。把项目复制到其他目录时，在新目录执行相同命令即可。

~~~powershell
Set-Location -LiteralPath 'D:\project\同花顺笔试'
node --version
~~~

### 7.2 配置模型

首次使用时，从 .env.example 复制一份 .env。下面的命令不会覆盖已有配置：

~~~powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
~~~

用文本编辑器在本机填写 .env。例如：

~~~dotenv
LLM_API_KEY=填写你自己的模型密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-flash
LLM_MAX_CALLS=20
~~~

这里的地址和模型名是本项目已经验证过的配置示例。密钥只由后台读取，不写进网页，也不要放进公开仓库。

| 配置名 | 用来做什么 | 当前是否需要 |
|---|---|---|
| LLM_API_KEY | 调用模型的密钥 | 真实聊天需要 |
| LLM_BASE_URL | 模型服务地址 | 真实聊天需要 |
| LLM_MODEL | 要调用的模型名 | 真实聊天需要 |
| LLM_MAX_CALLS | 这个服务进程最多发多少次模型请求，默认 20，允许 1～100 | 可选，用于限制一次演示的调用量 |
| FUYAO_API_KEY | 扶摇数据接口密钥 | 只有显式运行扶摇联网脚本时需要；当前缓存演示不使用 |
| IFIND_AUTH_TOKEN | 早期预留的配置名 | 当前服务不靠它在线拉取 iFinD 数据，单独填上不会自动开通实时取数 |
| PORT | 改本机服务端口 | 可选，需设置为启动进程的环境变量，不是写进 .env |

模型配置优先读启动进程的环境变量，没有时再读项目根目录的 .env。

### 7.3 准备数据

本机现有演示读取：

~~~text
data/snapshots/runtime/ifind-screening-sample.json
~~~

正常运行只读这份已核对的缓存，不会每问一句就再次查询金融接口。

**如果拿到的是公开仓库副本，不能假定里面有这份真实数据。** data/ 整个目录的业务文件被忽略提交，避免把真实受限数据或私有运行记录公开。没有缓存时，网页仍可启动，但无法复现这里列出的真实数字；演示真实筛选需要另行准备有使用权限的数据。

如果已经有本项目约定格式的两份 iFinD 原始响应，可以分别放到：

~~~text
data/snapshots/discovery/ifind-latest-pe-marketcap.json
data/snapshots/discovery/ifind-2026-11-09-pe-marketcap.json
~~~

然后运行本地整理脚本：

~~~powershell
node scripts/import-ifind-sample.cjs
~~~

这个脚本不会联网下载数据。它读取已有记录中的原始接口文本、解析表格、核对日期和数值，再生成缓存；不是把任意一份股票 JSON 改个名字就能用。需要的数据格式和原始字段说明见[数据说明](docs/data-sources.md)。

### 7.4 启动网页

~~~powershell
node backend/app/server.cjs
~~~

浏览器打开 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)。在输入框点击 ↑ 或按 Enter 发送，Shift+Enter 换行。停止服务在启动终端按 Ctrl+C。

默认只接受本机访问。改端口可以在同一终端这样启动：

~~~powershell
$env:PORT = '4174'
node backend/app/server.cjs
~~~

### 7.5 常见问题

| 现象 | 可以先检查什么 |
|---|---|
| 网页打不开 | Node 是否启动，端口是否被其他程序占用，地址是否和启动终端一致 |
| 提示缺少模型配置 | 项目根目录有没有 .env，三项 LLM 配置是否填全 |
| 提示模型额度已用完 | 检查 LLM_MAX_CALLS；它是本进程的请求计数上限，不等于模型账户的余额。新建聊天不会重置这个计数 |
| 三只以外的股票或其他日期显示待核验 | 当前缓存只覆盖指定三只和 2026-11-09，不能拿这份数据回答其他范围 |
| 改条件后仍看到上一轮结果 | 页面会标记为旧结果；需要重新确认并执行 |
| 结果已经出来，但解释暂不可用 | 先看逐项证据，也可点“重新生成解释”；不会重新拉金融数据或重新筛选 |

## 8. 数据从哪里来，能用到什么程度

### 8.1 当前实际使用的数据

当前筛选数据来自 **iFinD 已返回并保存在本地的真实响应**。不是模型生成的数据，也不是把测试里的假数值放进产品。

只使用 2026-11-09 的三只样本：

| 股票 | 代码 | PE TTM（倍） | 总市值，按方便阅读的单位表示 |
|---|---|---:|---:|
| 贵州茅台 | 600519.SH | 21.9856 | 1.8064 万亿元 |
| 平安银行 | 000001.SZ | 5.3067 | 2307.3637 亿元 |
| 招商银行 | 600036.SH | 7.0949 | 1.1013 万亿元 |

这些股票是验证产品流程的固定样本，不代表全 A 股，也不是有代表性的抽样。日期是缓存日期，不应称为今天的实时数据。

原始表格明确标出了 2026-11-09，三只股票的 PE 和市值与另一份“最新”查询逐只一致。但接口附带的参数说明仍写“交易日期：最新”，PE TTM 的基准日写“报表公告日期”。因此本项目只把它用于这个明确日期的本地演示，没有声称历史查询能力和历史财报可见时间已经验证通过。

每条可计算依据都保留原始字段名、原始值、单位和日期。市值统一按人民币元比较，展示和解释时允许精确换成亿元、万亿元；金额不能重复换算。

### 8.2 为什么暂时用缓存

扶摇估值接口在实际探测中返回业务码 2003，未取得可用业务数据，因此没有把“HTTP 请求成功”当成“拿到了数据”。之后按开发选择先用 iFinD 验证真实样本。

为了让模型额度和数据接口额度花在必要的地方，当前聊天、修改条件和重新筛选都复用同一份已核对缓存。这样也方便比较条件变化：结果变了，可以确认是条件改变，而不是中途行情换了一份。

这不代表在线金融数据接口已经全部接通。扶摇脚本仍保留，但不会自动成为当前筛选的数据源。

### 8.3 怎么判断入选、排除和待核验

单个条件只有三种结果：满足、不满足、待核验。数据缺失、日期对不上或口径不能确认，都不能当成满足，也不能随手填 0。

| 用户选择的组合 | 整体怎么判断 |
|---|---|
| 所有条件都要满足 | 有一项明确不满足，就未入选；否则，只要还有待核验项，就整体待核验；全部满足才入选 |
| 任意一项满足即可 | 有一项满足，就入选；否则，只要还有待核验项，就整体待核验；全部明确不满足才未入选 |

不能把“没有数据”说成“股票不好”，也不能因为一个条件满足就声称全部要求已经满足。

## 11. 每个可运行脚本怎么用

这些脚本都用 Node 和项目自己的模块，不需要额外安装依赖。命令在项目根目录执行。不要把整理数据的脚本误当成启动页面的命令。

### 11.1 backend/app/server.cjs：启动页面和后台

- 读取什么：页面文件、题库、提示词、模型配置；请求到来时读取本地缓存和会话。
- 做什么：在本机提供网页和后台接口，不会一启动就自动调用模型或金融接口。
- 怎么运行：node backend/app/server.cjs。
- 输出什么：终端显示本机访问地址，进程持续运行；实际对话保存在内存。
- 失败或重复运行：端口占用时启动失败；同一端口不能再开一份。停止并重启会清空会话，也会重置本进程的模型请求计数。

### 11.2 scripts/verify.cjs：检查预写文件有没有接错

- 读取什么：contracts/ 和 config/ 下的 JSON。
- 做什么：检查题库清单、同名题目和指标说明、文件引用、题目默认和选择项能否对上。
- 怎么运行：node scripts/verify.cjs。
- 输出什么：终端显示检查通过及文件数、指标数；不改文件、不联网。
- 失败或重复运行：有缺文件或约定不一致就报错退出，可反复执行。
- 要注意：这不是完整的数据格式认证，也不会证明金融数据真实可用。指标说明里的全市场启用标记仍保持关闭，不能因为两项样本通过就直接全打开。

### 11.3 scripts/generate-examples.cjs：重建填空示例

- 读取什么：市盈率题目和真实运行的检查函数，示例问句写在脚本内。
- 做什么：生成“还没填完”和“已经确认”的两种答案，方便看懂后台格式。
- 怎么运行：node scripts/generate-examples.cjs。
- 输出什么：覆盖 contracts/examples/ 中的两份市盈率示例；不联网。
- 失败或重复运行：读写或检查失败就报错；再次执行会重新覆盖同两份示例，不生成股票行情。

### 11.4 scripts/verify-model-intake.cjs：验证旧填空模块

- 读取什么：脚本里预先写好的三条测试问句；真实模式还会读取模型配置。
- 做什么：验证默认 PE、继续补充原答案、金额单位换算。它测的是底层旧填空接口，不是完整的新版聊天体验。
- 怎么运行：不加参数时只说明用法，不发请求；加 --mock 使用本地模拟；加 --live 才调用真实模型，最多三次。
- 输出什么：终端显示每条检查结果；模拟和真实模式分别写入 data/runs/model-intake-mock-check.json 与 model-intake-check.json，不记录密钥或提示词全文。
- 失败或重复运行：失败后停止后续检查；重复运行会覆盖相应摘要。每次 --live 都会产生新的计费请求，本脚本的三次上限单独计算，不是网页服务的计数器。

### 11.5 scripts/import-ifind-sample.cjs：整理已有真实数据

- 读取什么：第 7.3 节列出的两份 iFinD 原始响应和三只样本清单。
- 做什么：核对两份响应里的股票、字段、日期、PE 和市值，把亿/万亿等金额整理成人民币元。
- 怎么运行：node scripts/import-ifind-sample.cjs。
- 输出什么：生成或覆盖 data/snapshots/runtime/ifind-screening-sample.json，同时保留原始值、字段名、金额换算和日期限制说明。
- 失败或重复运行：缺列、金额无法识别、两份数值不一致或日期不合要求时拒绝写入；不会用错误输入覆盖旧缓存。检查成功后可重复重建。
- 要注意：零网络请求，只适配本项目已核对的这两份三股响应，不能当通用 iFinD 下载器。

### 11.6 scripts/refresh-sample-snapshot.cjs：单次探测扶摇

- 读取什么：FUYAO_API_KEY 和 config/sample-universe.json 中的三只代码。
- 做什么：默认不联网；显式加 --live 才发起一次只读估值快照请求。
- 怎么运行：node scripts/refresh-sample-snapshot.cjs；需要真实请求时再加 --live。
- 输出什么：业务成功后写 data/snapshots/runtime/fuyao-valuations.json，保留原始响应而不写密钥。
- 失败或重复运行：请求或业务失败就报错，不自动重试；每次再次加 --live 都是一次新的金融请求。
- 要注意：历史实测业务码是 2003，没有取得可用数据。即使以后此脚本成功，也不会自动替换页面正在使用的 iFinD 缓存或启用其他指标。

## 12. 网页和后台怎么接起来，调用量怎样控制

对一般使用者而言，只需操作聊天窗口。下表供接手代码的人定位入口。

| 接口 | 大白话用途 | 是否联网 |
|---|---|---|
| GET /api/health | 检查本机服务是否还在运行 | 否 |
| GET /api/bootstrap | 读取页面初始配置、数据状态和剩余模型请求数 | 否 |
| POST /api/sessions | 创建一轮新聊天和后台答案 | 否 |
| GET /api/sessions/:id | 读取这个临时会话的当前状态 | 否 |
| POST /api/sessions/:id/chat，带 text | 发送用户原话或点击的选项，由模型理解和回答 | 调模型 |
| 同上，带 action=confirm | 明确确认当前条件 | 否 |
| 同上，带 action=screen | 用已确认答案进入模型工具筛选和解释流程 | 调模型；金融数据读本地缓存 |
| 同上，带 action=explain | 只重新解释已完成的结果 | 单次模型请求，不重新筛选 |
| GET /api/evidence/raw | 按固定来源名称查看已有原始数据证据 | 否，不接受任意文件路径 |
| POST /api/reload-snapshot | 重新读取本地缓存，页面没有单独放这个技术按钮 | 否 |

旧的 /intake、/answers、/confirm、/screen、/resolve-unmapped、/save、/load 和 /api/strategies 接口仍用于底层兼容或测试，不是当前页面中的另一套表单流程。其中 /intake 会调用模型；旧保存、载入接口会读写本机策略文件，但页面没有这些入口。

当前只接受本机来源，请求体上限 16KB。模型密钥和金融密钥都不交给前端；工具不能执行模型提供的任意代码或访问任意路径。同一会话处理消息时会拦住并发重复请求，页面也会在等待时禁用按钮。

调用量按下面的规则控制：

- 普通业务消息或聊天选项通常调用一次模型。字段检查未通过时，最多让模型纠正一次；仍失败则保留原条件，不展示未保存的成功回答。
- 一次确认后的筛选，模型请求总数最多四次，包括必要的工具往返和至多一次解释纠正。两个工具都只读取本地数据和按答案计算。
- 解释失败后，单独重新生成只调用一次模型，复用同一份结果，不调用金融接口。
- 每个网页服务进程的请求总数受 LLM_MAX_CALLS 限制。工具往返和纠正也计入；新开对话不能绕过，服务重启后重新计数。它不是跨进程、跨天的账户账单限制。
- 网络错误不自动重试，避免不断消耗额度。没有拿到数据或工具没有完成，不能伪装成正常筛选成功。

## 13. 做过哪些验证，AI 参与了哪些工作

### 13.1 本地自动检查

~~~powershell
node scripts/verify.cjs
node --test backend/tests/*.test.cjs
node scripts/verify-model-intake.cjs --mock
~~~

最近一次代码验收为 **59 项自动测试通过**，题目和指标结构检查为 **12 个指标、30 份 JSON 通过**。这些测试不调用外部模型或金融接口；测试中的模拟数值只给测试用，产品服务不会把它们读成行情。

检查内容包括：

- 模糊意图、默认值、继续补充答案、替换经营指标后保留其他条件、用户确认和条件变化比较。
- 金额原数与换算值、报告期和日期、缺数据、日期不一致、样本外股票、未支持的指数范围。
- 模型返回错误格式、试图填写确认状态、未知字段、工具乱序或重复、没有执行工具却声称成功。
- 模型超时、解释连续失败时保留结果、单独重试解释不重新筛选、改条件后不能拿旧结果解释。
- 本机访问限制、请求体限制、并发重复点击和模型调用上限。

这并不意味着任意自然语言、任意复杂逻辑或所有金融接口都已经验证。完整场景和阶段记录见[测试说明](docs/testing.md)。

### 13.2 真实模型和真实数据验证

实际通过浏览器验证过 DeepSeek 的连续澄清、修改多个条件、确认后真实工具调用，以及根据本地真实数据解释结果。第 6.2 节的三条件结果已经完整跑通。

主代理记录的三个近期改造阶段分别用了 10、5、6 次真实模型请求，包含中途失败验证和定位调用，不是全部都成功。记录按阶段保存，不把模拟测试混进真实调用数，也不把这些阶段数当作整个开发期或用户自行调用的总数。对应记录见[AI 使用记录](docs/ai-usage.md)。

数据最初通过 iFinD 的“最新”和明确日期两次查询核对；扶摇做过一次估值接口失败探测。近期改造复用已有缓存，没有为反复调试再次调用金融接口。历史其他探测另有记录。

### 13.3 AI Coding 的使用和人工修正

开发中使用 Codex 组织代码工作，GPT-6 Luna max 参与基础实现。Luna 因账户使用额度限制中断后，主代理继续整合代码、复核接口、修正问题并做浏览器验收。产品运行时使用配置的 DeepSeek API，开发工具和产品里的选股助手不是同一个角色。

产品取舍由使用者提出和确认，AI Coding 承担实现与修改。下面列出的是评审和复核中发现并修正的问题，不把 AI 生成的内容当成无需检查的最终答案：

| 发现的问题 | 修正方式 |
|---|---|
| 把固定试卷直接摆到前端，让用户手工编辑 | 改成后台试卷，用户只聊天和看结果 |
| 预设话术处理了大部分问答，模型只做少量兜底 | 业务文本和聊天选项统一交给每轮模型调用 |
| 改经营含义时丢掉其他条件，或仍保留被替换的旧指标 | 按已有题目合并修改，保留其他条件并记录替换 |
| 正常的“市值下限500亿元”被当成无效回答 | 统一比较含义与金额单位，兼容模型的精确换算值 |
| 模型复制只读元信息导致误拦 | 统一输入格式；即使带回确认元信息，也不能代替用户确认 |
| 金额换一种单位就被解释校验拒绝 | 支持元、万元、亿元、万亿元的精确对应 |
| 解释失败导致已经算出的结果也丢失 | 结果与解释分开，保留真实结果，允许单独重新解释 |

更完整的经过、失败记录和未验证范围放在[AI 使用记录](docs/ai-usage.md)和[测试说明](docs/testing.md)，不把开发过程中的每次失败都堆在主流程里。
